3. **Settings live in environment variables / a local `.env` file** (template: `.env.example`). `.env` is in `.gitignore`, so keys never get uploaded.

## Database
4. All seven tables from the plan's "Data model" exist. I added two helper tables: `document_sections` (the cut-out Item 1 / Item 1A / customer notes, so the AI reads only those) and `ai_usage` (tokens per AI call, because the plan says to log tokens per job).
5. A few extra columns: `links.is_sample` and `events.is_sample` (to clearly mark hand-made SAMPLE data), `documents.external_id` (e.g. the SEC accession number, so the same filing is never stored twice), `nodes.extra` (SEC company number, Korean/Japanese stock codes), `impacts.path_links`, `how_much`, `timing`, `what_would_change_this` (fields the ripple explainer returns), and `events.summary` / `biggest_unknowns`.
6. **"The database refuses a link without a source"** is enforced by database triggers: a link can't be *inserted* as approved, can't be *changed* to approved unless it has a source whose quote was verified word for word, and its last verified source can't be deleted.
7. `followups.checked_at` stores `1d`, `1w` or `1m` (which check it is), since the plan describes it as "1 day, 1 week or 1 month after the event".

## SEC collector and section cutter (Phase 1)
12. The SEC collector stays at **8 requests per second** (SEC's limit is 10) and retries politely on "too many requests" errors.
13. For **foreign filers** (TSMC, ASE) there are no 10-Qs; they file 20-F (annual) and 6-K (current/quarterly). The collector treats 6-K like 8-K. 
14. "8-K from the last 4 quarters" = 8-Ks filed in the last 12 months, at most 8 per company by default (some companies file dozens; change with `--max-8k`). Only the main 8-K document is stored, not its attachments (press releases are exhibits) — a possible later improvement.
15. Raw downloaded HTML is also kept, gzipped, in `data/raw/` (not uploaded to GitHub) so every claim can be traced to exactly what was downloaded.
16. For a 20-F, "Item 1" is taken from **Item 4 (Information on the Company)** and "Item 1A" from **Item 3.D (Risk Factors)** — the 20-F equivalents.
17. Short documents (8-K, 6-K under 60,000 characters) are stored whole as a `full` section. 10-Qs get their Part II Item 1A (risk factors) plus customer-concentration sentences.
18. "Customer-concentration notes" are found by sentence search across the whole filing: a sentence is kept if it mentions a customer/supplier/vendor/foundry/sole source AND a share, "accounted for", "depend", "limited number of", etc. This catches the notes to the financial statements wherever they are. It lets some noise through (that's cheaper than missing a real link).

## Ripple tracer (Phase 3 code)
19. **Which way trouble flows:** `supplies` and `produces` pass trouble forward (supplier -> customer, producer -> material); `uses` and `makes_in` pass it backward (material -> company that uses it, place -> company that makes things there).
20. **Exposure score (0–100):** each link gets a strength = confidence weight (high 1.0 / medium 0.75 / low 0.45) × share factor (disclosed % scaled 0.35–1.0; unknown = 0.5) × alternatives factor (1 / (1 + 0.5 × number of other sources of the same thing)). A path's strength is the product of its links. A company's score combines all its paths (1 − product of (1 − path strength)), with a 15% bump if it is in the same country as the event. These numbers are starting points to tune once real events can be compared with what happened.
21. Paths can't loop back through a node or through another affected node. At most 5,000 paths per starting node (a safety cap; the current map is far smaller).
22. "Who might benefit" is found by code as a *candidate* list only: companies that also produce a hit material/part but are not on any path (e.g. Linde and Air Products for helium). The AI explainer decides the actual direction.
23. **SAMPLE links:** 51 hand-made links in `data/sample/sample_links.json`, all stored with `is_sample=1`, quotes start with "SAMPLE:", shares are made up. They're backed by one SAMPLE document so the "approved needs a verified source" rule still holds. One sample link (Micron -> AMD) is dated after March 2026 on purpose to test the "only links from before the event" filter. Remove them with `python -m ripple load-sample --remove`.

## Website shell
24. **No build step.** The plan suggests Tailwind / shadcn / Framer Motion / Cytoscape. I built the shell with plain HTML, CSS and JavaScript instead, so you can open the pages by double-clicking them, there's nothing to install, and they can be hosted free on GitHub Pages as they are. The design tokens (colours, fonts, spacing) all live at the top of `site/assets/style.css`, so moving to Tailwind later is straightforward. The big interactive "map explorer" (Phase 5) is the right place to bring in Cytoscape.js.
25. **Data file:** the pages read only `site/data/data.js`, written by `python -m ripple export-site` from the database. Right now it holds the SAMPLE data. Swapping in real data = `python -m ripple export-site --real-only`. It's a `.js` file (not `.json`) so pages work without a web server.
26. **SAMPLE events:** 4 hand-written events in `data/sample/sample_events.json` (helium shock, transformer lead times, SK hynix power cut, bromine licences). Their explanations imitate what AI job 3 will write; the "what happened next" price moves are made up. Every page shows a yellow SAMPLE banner and tags while any sample data is present.
27. Fonts: Fraunces (event headlines), Inter (everything else), JetBrains Mono (numbers, tickers, dates), loaded from Google Fonts.
28. **Light mode** (toggle top right; remembered per browser). The status colours are the same, but for *text* in light mode I use darker shades of red/green/amber/cyan so the text passes WCAG AA contrast.
29. Ripple diagram: a radial tree. The event sits in the middle, each ring is one more step away, and each branch gets a slice of the circle sized by how many companies sit beyond it, so lines don't cross. Hurt/helped/unclear are shown by colour **and** an arrow icon **and** a word. Low-confidence links are dashed. Hovering a line shows its source quote. Reduced-motion setting shows the finished ripple immediately.
30. Sparklines show the stock move after the event from the follow-up log (0 → 1 day → 1 week → 1 month), because the plan's data model only stores those three checkpoints.
31. The company page also works for places and materials (`company.html?id=helium`): it shows who produces it and who uses it. That covers the plan's "material or place page" too.
32. An "exposure score" for a *possible winner* is half its link strength, so possible winners don't outrank companies that are clearly hurt.

## AI jobs
33. **Switched off by default.** No call to Claude happens unless `ANTHROPIC_API_KEY` is set *and* `RIPPLE_AI_ENABLED=1`. `--dry-run` shows the exact prompt without sending anything.
34. Replies use Claude's **structured outputs** (a JSON schema), so the shape is guaranteed; code then checks the *content*.
35. Prompts are the plan's prompts, lightly tightened: job 1 also states which way a "supplies" link points and says to keep quotes in the original language (Korean/Japanese filings); job 3 is asked to say when it used general knowledge (`uses_general_knowledge`), and code then forces that impact to low confidence.
36. **Job 1 checker:** quote not found word for word → thrown out; unnamed or unmatched company → kept in a new `link_candidates` table with status `needs_review` (the review queue); matched → becomes a link with status `pending_review` and high confidence (stated in a filing). Even matched links wait for a person, because the plan says to review every link once by hand on the first pass. The same link found again just gets an extra source and a newer `last_confirmed`.
37. **Job 2:** only documents that mention at least one map node are sent (others are logged as skipped and never re-read). Its answer may only name nodes that were actually mentioned. Severity 3+ automatically triggers job 3. Results go in a new `event_checks` table.
38. **Job 3:** runs on `claude-opus-5-5` with adaptive thinking, effort "high", streaming, and server-side fallback switched on in case the model declines. Any company it names that the tracer didn't reach is dropped (no invented impacts).
39. Job 1 can also run through the **Message Batches API** (half price, results within a day): `python -m ripple ai extract-links-batch --limit 500`, then `python -m ripple ai collect-batch --batch-id ...`.
40. Tokens for every call are logged in the `ai_usage` table.
41. Model choice: jobs 1 and 2 on `claude-haiku-5-5` and job 3 on `claude-opus-5-5`, as you asked. Each can be changed in `.env` (`RIPPLE_MODEL_LINK_EXTRACTOR`, etc.).

## OpenDART and EDINET collectors
42. **Switched off by default**, like the AI jobs: each needs its key *and* its on-switch (`RIPPLE_OPENDART_ENABLED=1`, `RIPPLE_EDINET_ENABLED=1`). Tested only with fake API responses, because I had no keys and was told not to sign up for anything.
43. **OpenDART** collects, per Korean company: the latest annual report, the last 4 half-year/quarterly reports, and supply-contract disclosures (단일판매ㆍ공급계약체결) from the last year. The company's DART number is looked up from its stock code using DART's official company list.
44. **EDINET** lists filings day by day, so the first run walks back 400 days (to be sure to catch the latest annual report) and later runs only scan the days since the last run (saved in `data/raw/edinet/state.json`). It keeps annual, half-year, older quarterly, and extraordinary reports from our 5 Japanese companies. The Japanese "securities code" used to recognise them is the 4-digit ticker plus a 0 (e.g. Ibiden 4062 → 40620).
45. Korean and Japanese filings are stored **in the original language**. The section cutter finds 사업의 내용 (business) in Korean reports and 事業の内容 / 事業等のリスク (business / risks) in Japanese ones, plus sentences about customers/suppliers with a share. The link extractor is told to answer in English but copy quotes in the original language, so the word-for-word check runs against the original text.
46. Taiwan's MOPS (Unimicron, plus monthly revenue for TSMC/ASE) and the manual PDF folder for the European companies are not built yet — they were not in today's list.

## Zero-cost AI setup (second session)
47. **No paid API.** All AI work is done by a scheduled Claude Code session on your normal plan. The paid API route (`python -m ripple ai ...`) is still there but stays **off** (needs `ANTHROPIC_API_KEY` + `RIPPLE_AI_ENABLED=1`). The free-model backup (OpenRouter or Gemini) is also **off** (`RIPPLE_BACKUP_AI=off` by default).
48. **Saving the map between runs.** The database isn't in GitHub, and every scheduled run starts on a fresh machine. So the map's state (links, sources, review decisions, events, impacts, which sections were already read, AI usage) is saved as small text files in `data/state/*.jsonl` after every run and committed. Filing **text is not saved** (it would make the repository huge); it's downloaded again from SEC when needed. `python -m ripple state-load` rebuilds the database from these files; most commands do this automatically when the database is missing.
49. **Work-queue limits per day:** job 1 = at most 15 filing excerpts and 70,000 characters in total (roughly 18,000 tokens of reading); job 2 = at most 30 items; job 3 = at most 3 events, severity 3 and up, most severe first. These are settings at the top of `ripple/queue.py`.
50. **Excerpts, not whole sections.** For job 1, code keeps only the paragraphs of a section that mention customers, suppliers, sources, foundries etc. or a map company (max 6,000 characters per section). Quotes are checked word for word against exactly that excerpt, which is itself copied word for word from the filing. Sections with nothing relevant are marked as read without using AI.
51. **Order of work for job 1:** customer-concentration notes first, then annual "Business" sections, then 8-Ks, then risk factors; annual reports before quarterly ones. At ~15 a day the backlog of ~400 sections takes a few weeks, most valuable first.
52. **Job 2 pre-filter by code:** only items from the last 7 days; news must mention a map node *and* supply-related wording (shortage, plant, export, contract, capacity...); 8-Ks/6-Ks of map companies are included with the cover page cut off (the first 1,500 characters from "Item x.xx"). Everything else is logged as skipped, so it is never reconsidered.
53. `python -m ripple ai-status` returns exit code 3 when there's nothing to do, so the session can stop immediately (AI_TASKS.md tells it to).
54. Results and import reports are kept in `ai_work/history/` (small). The queue itself is not archived because it holds filing text.
55. **GDELT** (news) limits automated use to one request every 5 seconds and was throttling even that from this server, so the collector groups all map names into 4 combined searches, waits 10 seconds between them, and retries. Ambiguous names are searched in a specific form ("Meta Platforms", "Eaton Corporation", "helium shortage"); country names alone are not searched. I read your cut-off point 5 ("for ...") as "for anything on the map", which matches your resent message.
56. Free-model backup defaults: OpenRouter `meta-llama/llama-3.3-70b-instruct:free`, Gemini `gemini-2.5-flash`. Free model names change often, so the model is a setting (`RIPPLE_BACKUP_MODEL`).
57. **First job-1 run (done by this build session, following AI_TASKS.md):** 3 queues, 29 filing excerpts answered, 8 news/8-K items checked (none was a real supply event). Result: 15 links waiting as `pending_review`, 30 candidates waiting for a person (unnamed customers, or companies/places not on the map yet such as Hon Hai, Wistron, Sony, Kinsus, Singapore), 0 quotes rejected. **No link was approved.** 10 of the 12 Business (Item 1) excerpts in the third queue were left unanswered on purpose, so they stay in the queue for the daily session.
58. Lesson from that run: quarterly reports repeat the annual report's text. The queue now takes **all annual-report sections first**, and skips a paragraph if the same paragraph is already in today's queue for that company.
59. I recorded unnamed customers that have a disclosed share (e.g. "one direct customer represented 22% of total revenue") as candidates, as the plan asks ("keep unnamed links as placeholders"). I skipped generic statements with no named party and no share ("we rely on a limited number of suppliers").

## Daily automation and hosting
68. **GitHub Actions "Daily collect"** runs at **01:23 Hong Kong time** (17:23 UTC). That's about 1.5 hours before the 3am session, because GitHub sometimes starts scheduled runs late, and it avoids the top of the hour, when GitHub is busiest. It runs `python -m ripple daily-collect`: SEC filings → (OpenDART/EDINET only if you add their keys as secrets) → GDELT news → section cutting → the small AI queue → site data → saves `data/state/`, then commits and pushes to `main`. Costs nothing: Actions is free for public repositories and well within the free 2,000 minutes a month for private ones (a run takes a few minutes).
69. **A failed collector doesn't fail silently:** the other steps still run and commit, then the run is marked failed, and GitHub emails the repository owner about failed runs by default.
70. The SEC contact line must be added once as a repository **secret** called `SEC_USER_AGENT` (Settings → Secrets and variables → Actions). It is never written in the code.
71. Raw filings are kept between runs with GitHub's free cache (`data/raw`), so filing text never has to be downloaded twice. Each run only refills the text of the ~40 filings the next queues will use, plus recent 8-Ks the event checker hasn't seen.
72. News headlines (GDELT) are small, so their text **is** kept in `data/state/`, unlike filings.
73. **GitHub Pages** workflow publishes the `site/` folder whenever `main` changes and after every daily collect (a push made by a workflow doesn't trigger other workflows by itself, so it listens for the daily run finishing). One-time switch: Settings → Pages → Source: "GitHub Actions". The address will be https://yzymbiote.github.io/Ripple/. The private review page is **not** published (it lives in `review/`, outside `site/`).
74. A **Tests** workflow runs the automated tests on every pull request and on `main`.
75. **Fix: the website was never uploaded before.** The repository's starting `.gitignore` (GitHub's standard Python template) ignores any folder called `/site`, so the `site/` folder was left out of every earlier commit without any warning. I removed that one line; the website is now committed.
